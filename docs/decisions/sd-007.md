# SD-007 MCP server

Status: Agreed (decision log, 2026-10-13).

Recommendation: one FastMCP server exposing six tools and one resource, authenticated with an SD API key, runnable over stdio for local agents and over HTTP for remote ones.

| Tool | Input | Returns | Notes |
|---|---|---|---|
| `list_tree` | project, optional folder path | The subtree as nested JSON with paths, kinds and public flags | Cheap; agents call it first |
| `create_page` | project, parent path, title, markdown, optional summary and tags | The new node with path and version | Summary and tags supplied means agent mode: no model call |
| `update_page` | path, markdown, optional summary and tags, expected version | The new version | Rejects with a conflict when the version moved |
| `move_node` | path, new parent path, optional position | The new path | Rewrites the subtree paths |
| `publish_page` | path, public true or false | The public URL when published | Runs the optional Jev safety check if enabled |
| `search` | project, query, k | Ranked pages with path, summary and score | Semantic over embeddings; optional Jev rerank |

**Resource.** `sd://{owner}/{project}/llms.txt` returns the same text as the public route, so an agent can read a whole project without listing it.

**Rules.** Every tool description carries one worked example, because the model reads the description, not the README. Errors are structured: `code`, `message`, and `hint` with the tool to call next. Tools never return HTML, only Markdown and JSON. The server imports the service layer directly; there is no second HTTP hop.

**Options considered.**

| Option | Why not |
|---|---|
| A. Six tools plus one resource, service layer in-process | Recommended |
| B. One generic `call_api` tool that proxies REST | Models misuse open-ended tools; evals show lower task success |
| C. Twenty fine-grained tools | Tool lists that long hurt selection accuracy in small models |

**Reference: how ClickUp's official MCP shapes its Docs tools** (read from their live tool schemas on 2026-09-29). Four things worth copying:

1. Structure and content are separate calls: `list_document_pages` returns names and hierarchy with no content, `get_document_pages` returns content for chosen ids. SD's `list_tree` and a page read should split the same way.
2. `update_document_page` takes `content_edit_mode`: `append`, `prepend` or `replace`, so an agent can add to a page without reading it first. SD's `update_page` gets the same option.
3. Every description explains where the ids sit in a URL. SD tool descriptions will say how a path maps to a public URL.
4. Search returns a cursor and the description insists on paging until it is absent. SD's `search` takes `k` and returns `next` when more exist.

**Consequences.** Claude Code registers it with one line in `.mcp.json`; the README shows the exact config. The eval suite calls the tools through the MCP client, not the Python functions, so the descriptions are what gets tested.
