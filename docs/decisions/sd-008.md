# SD-008 Auth and security

Status: Agreed (decision log, 2026-10-13).

Recommendation: email and password with argon2 for people, long-lived API keys with scopes for agents, short-lived JWTs for sessions, and a short list of things SD never stores.

| Concern | Choice |
|---|---|
| Sign up and login | Email plus password, argon2id hash, no email verification in the MVP, `SIGNUPS_OPEN` env flag so self-hosters can close registration |
| Session | JWT bearer, 24 h, HS256 with a server secret from env, no refresh tokens in the MVP |
| Agents | API keys `sd_` prefix, shown once, stored as SHA-256 hash, scopes `read`, `write`, `publish`; revocable from `DELETE /me/keys/{id}` |
| BYOK secrets | Encrypted at rest with Fernet using a key from env; or per-request header `X-LLM-Key` that is used and dropped |
| Public pages | No auth, output sanitized by nh3, `Content-Security-Policy` with no inline scripts |
| Rate limits | Per SD-005, plus 10 login attempts per 15 min per email and IP hash |
| Never stored | Raw IPs (hashed with a daily salt), plaintext API keys, plaintext BYOK keys, password reset tokens after use |

**Options considered.**

| Option | Why not |
|---|---|
| A. Own auth as above | Recommended: same recipe as bubbles, fully understood, no lock-in |
| B. OAuth sign-in with GitHub or Google | Nice for a public instance, but adds a provider dependency and a callback URL to every self-host |
| C. fastapi-users library | Faster to wire, harder to explain in an interview |

**Consequences.** Password reset is out of the MVP; a self-hoster resets by CLI. Rotating the JWT secret logs everyone out, which is acceptable. Keys and secrets are documented in `.env.example` with a one-line reason each.
