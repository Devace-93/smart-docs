# SD-013 Shared identity: sessions from accounts.3m4.net

Status: Proposed (2026-10-16). Decider: Enrique.

Recommendation: Smart Docs stops owning identity. People sign up and log in once at the shared 3m4 identity service (`accounts.3m4.net`), which sets a `3m4_session` cookie on `.3m4.net`. Smart Docs verifies that cookie locally against the service's public keys and creates or refreshes its own `Account` row from the session claims. API keys (`sd_`) do not change. This record supersedes the sign-up, login and session rows of SD-008; the API key, BYOK and public page rows of SD-008 stay as they are.

| Concern | Choice |
|---|---|
| Sign up and login | At `accounts.3m4.net` only: e-mail and password, magic link, Google, GitHub, Microsoft, Discord. `/login` and `/signup` here redirect there with `return_to=/app` |
| Session | The `3m4_session` cookie: an Ed25519 JWT (15 min) refreshed by the browser at `accounts.3m4.net/api/session/refresh`; also accepted as `Authorization: Bearer <jwt>`. Verified with the JWKS at `/.well-known/jwks.json`, issuer `ACCOUNTS_URL`, audience `3m4` |
| Account row | Created on the first verified request (`identity_id` = the JWT `sub`) with the default tier. `email` and `handle` mirror the claims and are refreshed on every request |
| Handle | Global, owned by the accounts profile. It still drives `/{handle}/{project}/{path}`; a rename there renames the public URLs here, and the accounts profile page says so |
| E-mail verification | The claim `email_verified` gates every endpoint except `GET /api/v1/me` (`403 email_unverified`) so the editor can show "verify your e-mail" |
| Signups | `SIGNUPS_OPEN=false` refuses to create a row for a 3m4 user who has none yet |
| Agents | Unchanged: `sd_` API keys with scopes, created from a logged-in session, used on `/api/v1` and `/mcp` |
| Removed | Password hashes, `POST /auth/register`, `POST /auth/login`, the login rate limit table, `SECRET_KEY`, the `create-user` and `reset-password` commands |
| Data | Migration `002` deletes every account and what hangs from it. There were no real users on 2026-10-16 |

**Options considered.**

| Option | Why not |
|---|---|
| A. Verify the shared cookie locally, provision from the claims | Recommended: no request to the identity service on the hot path, one login for every 3m4 app, the hosted pages implement show/hide, confirm, OAuth and magic links once |
| B. Keep local passwords next to the shared session | Two ways to be the same person, two password stores to protect, and the "one login everywhere" goal is missed |
| C. Redirect to accounts with an OpenID Connect code flow and keep a local session | Standard, but a second session and a token exchange for nothing: every app already shares the `.3m4.net` cookie domain |

**Consequences.** A self-hosted instance needs a reachable accounts service (or a fork that keeps SD-008). `ACCOUNTS_URL` and `ACCOUNTS_INTERNAL_URL` join `.env.example`; the `api` container joins the `edge` docker network to read the JWKS by container name. Local renames of the handle are no longer possible from Smart Docs. The vendored verifier is `src/smart_docs/m4session.py`; keep it in step with `accounts/CONTRACT.md`.

**Decision:** Enrique sets the status in the index.
