# SD-013 Shared 3m4 chrome

Status: Agreed (2026-10-16).

Recommendation: the header and footer of every Smart Docs page follow the chrome shared by the other 3m4 apps (metrics, retro, 3m4), rebuilt in plain CSS and Jinja rather than imported.

**Context.** Smart Docs is one of several apps under 3m4.net that link to each other through the footer and the apps index. The other apps are Qwik and Tailwind and share one header (brand mark, nav links, theme toggle, Log in and Sign up buttons, mobile menu) and one footer (author credit, Source, apps index on the left; the app's own links and "Open source · MIT · © year" on the right). Smart Docs shipped with its own ad-hoc header and footer, so it looked like a different product.

**Options considered.**

| Option | Shape | Why not |
|---|---|---|
| A. Rebuild the shared chrome in Smart Docs's own CSS and templates | Same layout, slate scale, theme key `3m4.theme` and footer shape, written by hand in `app.css` and `base.html` | Recommended |
| B. Share a package or stylesheet across the apps | One published CSS file or component library | Couples a Python app to a Node toolchain and makes self-hosting heavier |
| C. Leave Smart Docs with its own look | No change | Breaks the one-family feel the footer links promise |

**Rules.** The removable "Built with Smart Docs" link from SD-009 stays in the footer. The instance name is the wordmark, so a self-hosted instance keeps its own name. Colors come from the same slate scale as the other apps, with blue as the accent.

**Consequences.** Any later change to the shared chrome has to be mirrored by hand in Smart Docs. The header exposes Log in and Sign up on public pages, which depends on `signups_open`.

**Decision:** Enrique sets the status in the index.
