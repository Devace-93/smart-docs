# SD-001 Goals and MVP scope

Status: Agreed (decision log, 2026-10-13).

Recommendation: ship an agent-native knowledge base as an MVP as soon as possible, with people and agents as equal users: backend tickets first, then the visual editor as frontend tickets.

**Context.** Two goals drive this project. First, build a knowledge base where agents are first-class users, and make that verifiable from the repo alone: an API an agent can drive, an MCP server, evals, and docs written for a machine. Second, give Enrique his own publishing tool for 3m4.net, open source so anyone can self-host it. The time box is a working MVP as soon as possible, built with AI assistance.

**Options considered.**

| Option | What ships in the MVP | Why not |
|---|---|---|
| A. Agent-native knowledge base, API + MCP first | Accounts, projects, folder and page tree, per-page public toggle, public HTML and Markdown, llms.txt per project, MCP tools, summaries and tags from a model, semantic search, sharing by link and per-person access, images and attachments, evals | Recommended |
| B. Notion-like app with a visual editor | A React or Qwik editor on top of A | Weeks of work before anything ships; the editor comes as frontend tickets after the backend instead |
| C. Issue triage agent on a public open-source repo | Classifier plus MCP over GitHub issues | Strong eval story, but not a product Enrique keeps using |

**MVP scope, in.** Register and login. Projects. Nodes: folders and pages in a tree, move and reorder. Markdown page body. Public toggle per page. Public routes: HTML render, raw Markdown, llms.txt. Model on save: summary and tags. Semantic search inside a project. MCP server with create, update, move, publish, search. Eval suite on seeded pages. Share by link and per-person access. Images and attachments on pages. README, Docker Compose, decision log in the repo.

**MVP scope, out.** Real-time collaboration. Page versions and history. Comments. Billing. Custom domains. Each is a future feature with its own epic.

**Frontend, next.** The visual editor is part of the project. Its frontend tickets are planned alongside the backend ones and start once the backend tickets they depend on are done.

**Consequences.** People use SD through the API, the MCP server, or any Markdown editor until the frontend tickets land; the web editor follows the backend tickets. Every out-of-scope item gets its own SD when it comes up.

**Decision:** Enrique sets the status in the index and edits this record if the scope changes.
